# backend/src/pipeline - the conversion engine

Order of use for one PDF page: `page-extract` → `layout` (+ `arabic`) → `process-page` decides text / OCR / image →
`convert-pdf` collects pages → `quran` → `preview` + `docx-builder`.

| File | Purpose |
| --- | --- |
| `arabic.js` | Arabic utilities: script detection, presentation-form → real letters, bracket mirroring, grapheme-safe reversing, **reversed-text detection**, **garbled-text-layer detection** (letter-frequency profile, unmapped glyphs). |
| `layout.js` | Layout analysis: attach floating diacritics to base letters, group lines, find column gutters, **visual → logical bidi ordering**, XY-cut reading order, table detection from ruling lines, paragraph building (alignment, bullets, line merging). |
| `page-extract.js` | Worker-side PDF reading with pdf.js: walks the operator list (glyphs with exact Unicode and position, ruling lines, image positions), renders pages with canvas, crops images, builds the text page model, computes page margins. Loads the pdf.js WASM decoders, so scans stored as JPEG2000 or JBIG2 (very common) are not rendered blank. |
| `process-page.js` | Per-page strategy: text layer → quality check → AI reading (if requested) → standard OCR → picture fallback (covers, ornaments, any page that fails); also the `exact` mode. Returns the page model + metadata for the report. |
| `scan-clean.js` | Prepares a scanned page for OCR: evens the paper of a page photographed with a phone (a shadow across it; a flat scan is left as it is), finds and crops the decorative frame, removes diacritics on heavily vowelled pages (keeping letter dots), normalises the text size. This raised letter accuracy on a real scanned book from 54% to 86%. Also erases ornament/header fragments that touch the crop edge, so they are not read as text. Paints out an uploader's stamp in the top left corner of a page (`eraseStamp`: "رفع عبد الرحمن النجدي … www.moswarat.com"), which was read as a line of nonsense joined to the chapter heading (a speck of the scan on its rows is no part of it), and a thin rule down the side of the page (`eraseThinRules`: the edge of the scanned page, broken by the deskew into short pieces, put ink on every row and made the line finder see one block). For the AI readers (`enhanceForAi`): even paper, contrast stretch, **deskew** (a page photographed askew is set straight), light sharpening; never binarised or smoothed, so diacritics keep their shape. A **faded print** (grey ink, not black: `evenPaper` would keep under 80% of its dark pixels, where a clean scan keeps 85-90%) is evened by its paper's own tone and its grey ink darkened instead, so the strokes stay whole (a faded first line read as "آذانشا ثُلثنا وَقَالَ هَسِيَ آلَكَ" now reads "أعادها ثلاثا وقال هى لك"); the darkened stars of a "* * * *" row, touching in their grey fringe, are told apart by `findSeparators` with the darker ink only. |
| `book-words.js` | Book-level word repairs from the book's own words: a doubtful word (`fixDoubtfulWords`), a dot slip (`fixDotSlips`), an alef maqsura with a dagger alef read as a ya with a hamza (`fixMaqsuraHamza`: "يتهادئ" → "يتهادىٰ", only for a word the book prints nowhere else and the Quran does not have), a numbered item's number read with a digit too many or as an alif (`fixItemNumbers`: "٣٢–" between ٢ and ٤ → "٣–", "ا-" before ٢ → "١-"), and a word split at a letter that does not join the next (`fixSplitWords`: "شيو خه" → "شيوخه" when the book prints "شيوخه" and one half is no word; "بز" in a line of names → "بن"). |
| `running-head.js` | printMatch running heads (`settleRunningHeads`). For a book without drawn heads, `settlePageNumbers` gives every page after the cover, up to the last number read, its printed number from the page sequence (misread digits outvoted; a blank page none), set by `docx-builder` as a centred footer of that page; `fixHeadingsFromContents` reads the book's table of contents and writes the calligraphic chapter titles ("كتاب الاعتكاف" for "كَاٱبْدُ لِأَعْشِكَافِكْ") and the فَصْلٌ ornament over each "[في …]" heading as the contents name them. The contents are read as one stream of titles (the reader joins their lines and misreads their digits) and matched to the book's headings in order; a title the reader kept as a picture at the top of its page is written as text. The last page of the contents counts with only an entry or two; a chapter that begins down a page ("* * *" then "كتاب الفرائض") is matched as a short centred line there; another heading is rewritten only when it has as many words as the contents entry ("ترجمة الإمام العلامة" stays, though listed as "ترجمة المؤلف"); a raised note mark after a title stays. |
| `wasla.js` | Hamzat al-wasl (ٱ) in a vowelled book that prints it: the line reader writes a plain alif or takes the mark for a hamza ("أَلطَّهَارَةُ"); when those slips show over the book that it prints ٱ, its wasla alifs are written ٱ. A sukun on the article's lam before a doubled sun letter ("الْنَّجَسِ") is dropped in every book. Runs over the whole book after `book-words`. |
| `ocr.js` | Tesseract (local models; Arabic-only by default, which is far more accurate on Arabic books) → lines → paragraphs using the same layout rules; marks low-confidence words; drops only short noise lines, never real text; recycles/retries workers. Repairs the ﷺ glyph (read as junk tokens) only right after "رسول الله" / النبي / محمد (`fixHonorifics`). |
| `vision-ocr.js` | Optional **AI reading** of page images (Anthropic API via the official SDK, or a local Ollama model): transcription prompts, answer parsing, flow-layout blocks. A local model (Qari-OCR through `llamacpp`, or a general model through Ollama) reads the page **line by line** (`readPageByLines`), keeps only Arabic-script letters (`cleanArabicLine`), keeps the marks Qari reads on a sparsely vowelled line (a general Ollama model loses only its short vowels there: shadda, tanwin, dagger alef and hamza stay), writes the dagger alef of هٰذا / هٰؤلاء back where it was read as a letter (`fixDaggerAlef`: "هنذا", "هلذا"), turns round brackets read the wrong way ("]…["), sets the page number standing alone under the text apart (read by the shapes of its digits), sets a line's years and references by the shapes of their digits (`lineNumbers` in `page-digits.js`: a slash or a dash between two numbers keeps them one reference, "١٢٥/١٠", "١٤٢ـ١٦٧"), reads a short line it read as nothing again at twice the size ("( ب )"), reads a numbered item's number that opens a line by the shapes of its digits where the reader wrote a letter or another digit ("ه" → "٥ـ", "٧" → "٦ـ"), turns a title's half-reversed bracket round ("]في …]" → "[في …]"), raises the mark of a page's note in the text (`raiseNoteMarks`: "والفقه(١)", superscript in Word and in the preview; a mark read as a line of its own over a title goes back to the title's end), and `groupLines` turns the lines into paragraphs, headings and `[bracketed]` titles from the geometry. |
| `text-lines.js` | Splits a page body into its text lines (ink rows; floating marks are joined to their line; the line spacing is found from the periodic rhythm of the page, a spacing that does not come again at twice its length (the marks over a line and under it, in a book set with wide leading) being none, and touching lines are cut at the quietest rows) and reports the ink extent of each. Also finds the drawn rule of a running header, the rule above the footnotes, the dot leader of a table of contents line (`findLeader`: the title is read by the reader, the page number by the shapes of its digits), and the page number alone under the text (`footNumberBox`: the narrow ink group centred under the text block, specks of the scan on its row aside). |
| `token-confidence.js` | Per-word confidence from the model's token probabilities, counted on the **letters** (a doubt between fatha and damma is not a doubt) and the other letters it considered (ف/ق, ب/ن …) as alternatives. |
| `quran.js` | **Quran guard**: finds ﴿…﴾ quotations (and, for OCR/AI text, unbracketed passages backed by rare-word evidence), aligns them to the Mushaf word-by-word (tolerates missing glyphs, repeated verses, citations), repairs letters/diacritics, checks `[surah: ayah]` citations. |
| `docx-builder.js` | Builds the .docx with the `docx` library: one section per PDF page (original size, margins from content), RTL paragraphs/runs, complex-script fonts, tables, images, headings, highlights, and Word comments listing the other possible readings of a doubtful AI-read word. A page's printed number (`footer`) is a centred footer of its section; a page without one gets an empty footer, so it does not show the number of the page before. Verses of poetry go in a borderless table of two equal columns (sadr on the right, ʿajuz on the left); `printMatch` keeps two centred tab stops instead. |
| `preview.js` | Writes/reads the page-by-page preview (NDJSON) used by the in-app preview. |
| `convert-pdf.js` | Orchestrates a whole PDF on the worker pool, document-level consistency, Quran guard, report, docx. Also option normalisation. |
| `convert-image.js` | Images (JPG/PNG/WebP/TIFF/BMP/GIF) → OCR → docx (or the picture itself in `exact` mode). |
| `convert-text.js` | `.txt/.md/.csv` → docx with per-paragraph direction detection. |

Page model (shared by all converters, the docx builder and the preview): `{ n, width, height, margins, method, blocks[] }` where a
block is a paragraph (`runs`, `dir`, `align`, `fs`), a `table` (cells with paragraphs) or an `image`.
